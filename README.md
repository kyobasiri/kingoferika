# ムーンエリカ ゲーム本体（段階1：骨組み）

エディタの書き出したJSONを読み込み、エリカ1体が歩く・ジャンプする・技を出すところまで。
段階1では対戦相手の代わりに、動かない「ダミー」（エリカの立ち絵を薄く表示）を置いています。
近距離技と遠距離技の切り替え、当たったときのヒットストップ、キャンセルの確認に使います。

## 動かし方

```bash
npm install
npm run dev          # 開発用サーバー（http://localhost:5173）
npm run build        # 型チェック → dist/ に書き出し（公式サイト・Tauri に載せるもの）
npm run check:det    # Node で決定性チェック（ブラウザ無しで計算部分だけ動かす）
npm run build:rules  # 計算の決まり（src/game/rules）を、エディタ用の tools/editor/rules.js に書き出す
```

### 技の調整（F4でエディタと切り替え）

`npm run dev` で動かしているときは、ゲーム中に **F4** を押すと判定エディタに切り替わります。

- 今出している技・フレームがエディタで開きます（ゲームはその場で止まります）
- もう一度 **F4**（または上の「ゲームに戻る」）でゲームに戻ると、
  エディタの内容がそのままゲームに反映され、`public/chars/moon_erika/moon_erika.all.json` にも保存されます
- ページの再読み込みは起きないので、位置などはそのまま続きから試せます

エディタ本体は `tools/editor/editor.html`（v18 をそのまま置いたもの）。新しい版に更新したら、このファイルを差し替えてください。
エディタは開発サーバーだけで使い、`npm run build`（公式サイトに載せるもの）には入りません。

別の場所でエディタを使った場合は、書き出した `moon_erika.all.json` を `public/chars/moon_erika/` に上書きして、ブラウザを再読み込みすれば反映されます。

### 60fpsで動いているかの確認

デバッグ表示の1行目に「計算 ○回/秒」と「描画 ○回/秒」が出ます。
計算が60回/秒なら、ゲームは正しい速さで動いています。描画の回数は画面のリフレッシュレートに合わせて変わります（120Hzの画面なら120）。

## 設計の決まりごと

1. **計算と描画を分ける**：計算は1秒60回固定（`step()`）。描画は画面の更新ごとに最新の状態を描くだけ。
2. **同じ入力なら同じ結果**：`sim/` の中では小数・時刻・`Math.random()` を使わない。位置は1px＝1000の整数。
   ジャンプは「放物線の式」で毎フレームの高さを出す（足し算の積み重ねで誤差がたまらない）。
3. **状態を丸ごと保存・復元できる**：`GameState` は素のデータだけ。`structuredClone` でコピーすれば巻き戻せる。
   入力履歴も状態に入れているので、巻き戻した後のコマンド入力・先行入力も元通りに動く。
4. **計算と演出を分ける**：計算は「当たった」「暗転した」という知らせを返すだけ。火花は `render/fx.ts` が出す。
5. **反応を遅らせない**：
   - ボタンを押したフレームに技の1コマ目を描く（押してから開始まで 0F。デバッグ表示で確認できる）
   - フレームの間に押して離した短いタップも拾う（キーを押した瞬間に印を付ける）
   - 同時押しは「待ってから出す」のではなく、先に単発を出して3F以内なら上書きする
   - ヒットストップ中のキャンセル入力は予約して、明けた最初のフレームに出す
   - 60Hz画面の間隔のゆれを吸収して、計算と描画の組み合わせが1Fぶれないようにする
   - canvas は `desynchronized`（対応ブラウザで描いた絵を早く画面に出す）
   - アトラスは読み込み直後に一度描いて、試合中の初回表示で止まらないようにする

## ヒットバック・ガードバック（押し返し）

- 技（段）ごとに `hitPush`（ヒットバック）・`guardPush`（ガードバック）を px で設定（エディタの「性能」欄）。無ければ 40px / 60px。
- システム設定の「押し返し」→「押し返しにかかる時間(F)」（`pushback.pushFrames`、初期値8F）の間に、最初は速く・だんだん遅く下がる。
- ヒットストップが明けた最初のフレームから下がり始める。
- 相手が画面端で下がれない分は、攻撃した側が下がる（飛び道具のときは撃った側は下がらない）。
- ゲームではダミーを 8 キーでガードの状態にして確認できる。デバッグ表示に、ダミーとの距離と今回下がった距離が出る。

## エディタ v21 で増えた項目（ゲームも対応済み）

| 項目 | 場所 | ゲームでの動き |
|---|---|---|
| 歩く速さ・ジャンプ（高さ・滞空・前／後ろの横距離） | キャラ設定 | キャラごとの値を使う（踏み切り・着地はシステム設定の共通値） |
| コマンド（出し方・方向・ボタン・空中・距離） | 技の「基本」 | 選んだ内容（`cmd`）で技を出す。文字の「コマンド（メモ）」は説明用 |
| 着地硬直 | 空中技の「基本」 | 空中技の途中で着地したときの硬直 |
| 上がる高さ | コマの「このコマで進む距離」の横 | 技中に上下に動く。技の終わりに空中なら落ちる |
| 飛び道具の出す位置・届く距離・消えるまで・当たる回数 | 技の「性能」 | そのとおり動く |
| 66/44の受付 | システム設定の「input」 | 2回目までの受付 |
| 溜め | 技の「性能」 | 押しっぱなしで指定したコマを繰り返して待つ。待った時間で段階が上がる |
| つながり確認 | 右上（攻撃技） | ゲームでは使わない（エディタで確認するだけ） |

ダミーは立ってガードするので、ガード属性が「下段」「ガード不能」の攻撃（溜めの段階で変わったものも含む）はガードできず、「ガード不能」などの文字が出る。

## コンボ表示とダミー（トレーニング）

- 相手がくらっている途中（のけぞり中・空中くらい中）に当たると、コンボが続く。2ヒット以上で「○ HITS」を出す（本番の対戦でも出す）。
- トレーニングでは、合計ダメージと最後の1発のダメージ・補正も出す（`new Game(canvas, data, { mode: 'training' })`。本番は `mode: 'match'`）。
- ダメージ＝技のダメージ ×（溜めの段階の％）× コンボ補正（技単位で1つごとに−10%、最低50%）×（カウンターなら120%）。数値はシステム設定の「コンボ補正」「カウンターヒット」。
- ダミーの状態（8キー）：ニュートラル（くらう）→ しゃがみ → 立ちガード → しゃがみガード → 垂直ジャンプ。
- カウンターヒット（9キー）：コンボの1つ目の技がカウンターになる（ダメージ1.2倍、最初の1発ののけぞり＋3F・ヒットストップ＋5F）。
- ダミーは、くらい・ガード・空中くらい・ダウン・起き上がりの動作を技データから使う。ダウン・起き上がり中は当たらない。
- エディタでも、上の「相手」で同じ状態とカウンターヒットを選べる。当たったときのヒット数・合計ダメージ、つながり確認のコンボのヒット数・合計ダメージが出る。

## 計算の決まりは1か所（エディタとゲームで共通）

- 段の数え方・発生と有利・技中の移動・押し返し・ジャンプの高さ・ダメージと補正・コマンドの読み方・初期値は、`src/game/rules/index.ts` にだけ書いてある。
- ゲームはそれを直接使い、エディタは `rules.js`（グローバル変数 `GameRules`）として読み込んで使う。エディタの中に計算の式は書かない。
- F4 で開くエディタには、開発サーバーがその場で作った `rules.js` を渡すので、`rules/index.ts` を直せばすぐ両方に効く。
- アーティファクト版のエディタを更新するときは、`npm run build:rules` で作った `tools/editor/rules.js` を `editor.html` と一緒に載せる。

## チェックと照合（調整で破綻させないために）

- **エディタの「チェック」タブ**：やってはいけない状態を一覧にする（タブの数字は件数。赤＝エラー、黄＝注意）。
  - ゲームに必要な動作が無い／キャンセル先・派生先・飛び道具が存在しない
  - キャンセル受付・派生受付・飛び道具・暗転・溜めのフレーム番号やコマ番号が、技の長さに合っていない（コマの増減でずれた）
  - 段ごとの設定が今の段の数より多い（段がずれた可能性）
  - コマンドがまったく同じ技がある／どこからも出せない技がある
  - ヒットバック0、最速より速い発生、中段なのにしゃがみに当たらない、密着で空振りする、自分自身に目押しで何回つながるか
- **IDの変更**：キャンセル先（:hit 付きも）・派生先・出す飛び道具も一緒に書き換える。ゲームが名前で使う動作（idle など）は変えられない。
- **計算の照合**：F4 でエディタから戻るたびに、エディタとゲームの計算（全体・発生・段の始まり・連打の上限・ダメージ・コンボ補正・押し返し・ジャンプの高さ）を比べる。
  食い違いがあれば「計算の食い違い○件」と出て、内容は開発者ツールのコンソールに出る。

## 仮の値・段階1で入れていないもの

- 項目が無い古いデータでは、歩く速さ（前4px/F・後ろ3px/F）、後ろジャンプの距離（前と同じ）、66/44 の受付12F、飛び道具を出す位置（前150px・高さ190px）を使う。
  エディタで開くと、これらの初期値が項目として入る。
- 相手のくらい・ガード・ダメージ・ゲージ・投げの成立・振り向き以外の対戦の処理は段階2以降。
- 超必殺技はゲージ無しで出せます（ゲージは段階2）。MAX超必殺技・ガードキャンセルはまだ出せません。
